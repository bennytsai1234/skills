# Compass

把對話恢復成正確的決策狀態；使用者要方案時，再從已確認內容編譯成最小充分方案。依使用者的要求選模式：要「整理目前確定什麼」或對話已失真 → 校正；要「整理成方案／計畫」 → 收斂成方案。

兩種模式共通：

- 讀取目前完整對話與既有草案，不要求使用者重述已存在的資訊。
- 分開「使用者明確說過或確認的目標、限制與決定」「模型自己的推論、偏好與候選做法」「仍然開放的部分」「已被否定、取代或取消的內容」。模型說過、提過很多次或沒被反對，都不會讓它升格成使用者決定。
- 只有不同答案會實質改變後續分析或方案，而且無法從目前脈絡推出時，才列為需要使用者輸入的問題；不要把開放問題擅自壓成 A/B。
- 長度由需要區分的決策狀態決定：先保留會改變判斷的語義，再刪除重複與噪音；不為了短而把不同決策狀態壓成同一句，也不為了完整而重建整段歷史。
- 已被要求移除或不再提的內容直接省略，不留下「已移除」「不再採用」之類的墓碑。
- 除非使用者明確要求查證，不額外呼叫工具、瀏覽 repo、寫 code、跑測試或做新研究。

## 校正模式

輸出前讀取 `references/discussion-checks.md`，逐項檢查本輪對話是否失真，把模型自行升格的內容降回正確層級。依實際情況選用以下區塊，不硬湊格式：

- **目前確定**：使用者已表達或可直接由既有內容確定的事項。
- **模型目前的判斷**：可以說明偏向與理由，但明確保持它是模型判斷。
- **仍然開放**：真正尚未收斂的部分，不替使用者關閉選項。
- **真正需要你輸入**：只有阻塞時才出現；不固定用問題收尾。

校正後停在討論階段：不生成執行計畫，不宣告「可以開始」「就這樣定了」，也不自行切換到執行。

## 收斂成方案模式

既有 plan 只是輸入之一，不是權威；權威是使用者已確認的意圖、限制、既有行為，以及缺少就會使需求無法成立的必要連帶。

1. 輸出前讀取 `references/plan-checks.md`，逐項跑方案資格檢查。
2. 抽取已確認的目標與限制、必須維持不變的既有行為、必要連帶，以及真正未決且會實質改變方案的事項。
3. 對既有 plan 的每一個 state、branch、abstraction、fallback、retry、驗證、資料欄位、層級與額外修改重新驗證資格。一個項目只有在直接對應已確認需求、拿掉會使某個已確認需求在已知路徑上失敗，或為維持使用者要求保留的既有行為所必需時，才進入方案。對額外項目問：「不做這件事，哪一個已確認需求會在什麼實際路徑上失敗？」答不出來就沒有資格。
4. 保留會改變範圍、授權、執行順序、驗證方式或使用者下一步的語義，再壓縮重複語意與沒有可觀察差異的狀態；不要把必要條件壓成只有標題或口號。
5. 輸出新的方案，等待使用者確認，不把方案自動視為已接受。

依情況使用下列結構：

- **目標與不變項**：真正約束方案的已確認內容。
- **最終方案**：只放有執行資格的內容，讓使用者可以安全理解成「照這份做，實作者只做這些就能完成目前需求」。
- **真正未決**：只有不同答案會實質改變方案、且脈絡推不出答案時才出現。
- **非方案備註**：可選，最多三項、每項一句，沒有執行權；沒有就省略。

現有資訊真的不足以形成正確方案時，指出最小阻塞缺口，不自行補出新需求。
