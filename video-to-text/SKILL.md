# video-to-text

把影片網址轉成一份乾淨、可直接使用的繁體中文逐字稿。

設計重點：**能抓現成字幕就絕不浪費算力去辨識**。YouTube／B站大多有字幕，秒抓即可；抖音幾乎沒有字幕，才走語音辨識保底。

---

## 何時使用

使用者貼出影片連結（YouTube／Bilibili／抖音，或其他 yt-dlp 支援的平台），並表達想要逐字稿、字幕、影片文案、把影片轉成文字、或想討論影片內容時。

支援的網址範例：

- `https://www.youtube.com/watch?v=xxxx`、`https://youtu.be/xxxx`
- `https://www.bilibili.com/video/BVxxxx`
- `https://v.douyin.com/xxxx/`（抖音短連結會自動展開）

---

## 前置依賴

第一次使用前需確認以下工具已安裝；腳本啟動時也會自動檢查，缺什麼會明確提示。

| 依賴 | 用途 | 安裝 |
| --- | --- | --- |
| yt-dlp | 抓影片資訊、字幕、音訊 | `pip install -U yt-dlp` |
| ffmpeg | 抽取/轉換音訊 | `sudo apt install ffmpeg` |
| faster-whisper | 本地語音辨識（預設引擎，可抽換） | `pip install faster-whisper` |
| opencc | 簡體轉繁體 | `pip install opencc` |

> 這些都在本機執行，不需要任何雲端 API、不需要付費帳號。

---

## 使用方式

在 Claude Code 中，使用者貼出網址即可。請執行：

```bash
python scripts/transcribe.py "<影片網址>"
```

腳本會自行完成下載、抓字幕／辨識、清洗、簡轉繁、輸出。

完成後：
1. 讀取產出的 `.txt` 檔內容。
2. 把逐字稿全文帶進對話，讓使用者直接接續討論或做後續處理。
3. 簡短回報：檔案路徑、來源資訊、大約字數，以及這份逐字稿是「抓字幕」還是「語音辨識」得到的。

---

## 執行流程（腳本內部會做的事）

0. **環境檢查** — 確認 yt-dlp、ffmpeg、faster-whisper、opencc 是否就緒，缺則提示安裝。
1. **解析網址** — 判斷平台；抖音短連結先展開成完整網址。
2. **抓影片資訊** — 取得標題、作者、時長、影片 ID，用標題當輸出檔名（自動清掉非法字元）。
3. **優先抓現成字幕** — 列出字幕軌；有人工字幕抓人工的，只有自動字幕抓自動的。成功即跳過辨識。
4. **沒字幕才語音辨識** — 下載並抽出音訊，丟給辨識引擎轉文字。**此步驟是獨立可抽換模組（見下方）。**
5. **清洗文字** — 統一去除時間戳、序號、格式標記，合併破碎句子，清掉自動字幕的重複行。
6. **簡轉繁** — 用 OpenCC `s2twp` 轉成台灣正體（連「視頻→影片、軟件→軟體」等慣用詞一起轉）。
7. **輸出** — 存成純文字 `.txt`，檔名用影片標題，開頭附一行來源資訊；下載的音訊預設自動刪除。

## 可調參數

打開 `scripts/transcribe.py`，最上方有一段設定區，常用的都在那：

- `OUTPUT_DIR` — 逐字稿存放資料夾
- `WHISPER_MODEL` — 辨識模型大小（預設 `medium`；想更快可改 `small`／`base`）
- `KEEP_AUDIO` — 是否保留下載的音訊（預設 `False`）
- `OPENCC_CONFIG` — 簡轉繁設定（預設 `s2twp`）

---

## 抽換語音辨識引擎

語音辨識被獨立成單一函式 `transcribe_audio(audio_path) -> str`，介面固定是「丟一個音訊檔路徑進去，回傳一段純文字」。

要換成自己的本地模型時，**只需改寫這一個函式內部**，其餘流程（下載、清洗、簡轉繁、輸出）完全不用動。函式上方有清楚的註解標示替換點。

## 故障排除

- **抖音抓不到 / 報錯**：抖音反爬較嚴格，必要時為 yt-dlp 帶上瀏覽器 cookie（`--cookies-from-browser`）。
- **B站拿不到 AI 字幕**：部分 AI 字幕需登入；可改走語音辨識，或為 yt-dlp 帶 cookie。
- **辨識很慢**：把 `WHISPER_MODEL` 調小，或改用 GPU 版設定。
- **某些詞沒轉繁**：OpenCC 詞庫有限，可在輸出後自行做詞彙替換。
