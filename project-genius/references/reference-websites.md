# Reference Website Protocol

Use reference products carefully. A reference is an anchor, not a license to copy.

**Reference pinning is mandatory in Stage 1 Step 1.2**: the user MUST
provide (or pick from agent-proposed candidates) 3 reference products
before Stage 1 can complete. See `convergence-protocol.md` § Reference
Pinning Protocol for the full rules.

## Reference modes

1. No reference: generate from brief and user goals.
2. Reference-first: user wants the product to feel close to one to three references.
3. Hybrid reference: different references inform different layers.

## Layers to separate

When a user provides a reference, classify what they want to borrow:
- product positioning.
- page structure.
- navigation pattern.
- visual style.
- component style.
- interaction behavior.
- content tone.
- media style.
- technical pattern.

## If the reference cannot be inspected

Do not pretend to have seen it. Ask for:
- screenshots.
- screen recording.
- copied text.
- sections they like.
- a description of what should be borrowed.

## What not to copy

Do not copy:
- trademarked assets.
- proprietary brand identity.
- copyrighted imagery or video.
- exact copywriting.
- private product behavior that is not visible or described.

## Reference output

Summarize references as:
- what to learn.
- what to avoid.
- how to adapt it to this product.
- which modules it affects.

If a visual or behavioral detail is inferred from a reference site or
screenshot, record it in the target document's `Sources & Confidence` block as
inferred until the user confirms it.
