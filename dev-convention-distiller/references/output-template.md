# 輸出模板

最終輸出包含兩部分:CLAUDE.md 本體（code block 包住)+ 維護指南。以下是骨架,實際產出時填入從訪談 + 掃描萃取的內容,並刪除所有 ⟨說明文字⟩。

---

## 第一部分:全域 CLAUDE.md 本體

用單一 code block 包住整份,讓使用者一鍵複製到 `~/.claude/CLAUDE.md`。

骨架如下（分類依使用者實際情況取捨,空的分類就刪掉,不要硬湊):

````markdown
# 個人全域開發準則

> 這份檔案是我的個人開發準則,對我所有專案生效。它描述「我這個人怎麼開發」,而非任何單一專案的細節。AI agent 在協助我時應遵循這些準則,除非特定專案的 CLAUDE.md 另有覆寫。

## 協作慣例

⟨怎麼跟 AI agent 一起工作。這通常是最重要的一塊,放最前面。每條祈使句,精簡。範例方向:⟩
- 動手修改前,先說明你的計畫並列出預計改動的檔案,等我確認後再開始。
- ⟨改動範圍約束⟩
- ⟨何時該停下來問我而非自行決定⟩
- ⟨改完後的驗證期待⟩

## 工作流程原則

⟨寫程式的流程慣例。範例方向:⟩
- ⟨測試先行 / 小步提交 / 重構守則等⟩

## 編碼通則

⟨只寫真正語言/框架無關的編碼原則。具體到某 API 的不寫。範例方向:⟩
- 相依一律透過建構子注入,避免 service locator 或靜態全域存取。
- ⟨錯誤處理態度⟩
- ⟨可讀性 / 命名的優先序⟩

## 溝通與產出偏好

⟨希望 agent 怎麼回應、用什麼語言、產出風格。範例方向:⟩
- 一律使用繁體中文回應。
- ⟨精簡 vs 詳細⟩
- ⟨不確定時:直接建議 vs 先列選項⟩

## 待我確認（暫定）

⟨可遷移性有點模糊、或只有單一來源支持的條目放這裡,跟確定項分開。讓使用者裁決後再決定是否上移。⟩
- ⟨暫定條目 1 — 為何待確認的簡短說明⟩
````

**填寫原則:**

- 每條準則祈使句,精簡到 agent 能直接遵循。
- 協作慣例放最前、著墨最多——這是可遷移價值最高的一塊。
- 編碼通則嚴格把關:只要稍微綁到某框架的具體 API/套件,就不該出現在這份通用版。
- 「待確認」區塊務必跟確定項目視覺分開,不要混淆。
- 整份保持克制。寧可少而精,不要塞一堆稀釋重點。

填完後,在 code block 外用幾句話向使用者說明:這份放 `~/.claude/CLAUDE.md`、對所有專案生效、哪些條目是暫定待他確認的。
