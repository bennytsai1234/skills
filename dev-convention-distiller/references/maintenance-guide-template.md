# 維護指南模板

這是產出的第二部分。目的是讓使用者**自己**能長期維護這份 CLAUDE.md——核心是把「可遷移 vs 專案特有」的判斷力交給使用者,讓這份檔案能隨經驗自我演進。

# 全域 CLAUDE.md 維護指南

## 這份檔案放哪、怎麼生效

把上面那份 CLAUDE.md 存到 `~/.claude/CLAUDE.md`（使用者家目錄下的 `.claude` 資料夾）。Claude Code 在任何專案啟動時都會自動載入它,所以它對你所有專案無條件生效。

如果某個專案需要覆寫或補充,在那個專案的 repo 根目錄另放一份專案層級的 `CLAUDE.md`——專案層級會疊加在全域之上。

## 黃金法則:加任何一條前,先過這道關卡

這份檔案對**所有**專案生效,所以它的健康完全取決於一件事:**只放可遷移的準則,不放專案特有的東西**。

每次想加一條準則,先問自己一句:

> **「把這條準則搬到一個完全不同語言/框架/領域的新專案,它還成立嗎?」**

- **還成立** → 可以加。例如「動手前先說明計畫」「相依一律建構子注入」。
- **不成立 / 換專案就沒意義** → 不要加到全域,它屬於那個專案的 CLAUDE.md。例如「這個專案用 PostgreSQL」「OrderService 放在某資料夾」。

判斷不出來時,寧可先不加,或先放進「待確認」區塊觀察。

## 怎麼判斷該修剪掉某條

最明確的訊號:**某條準則在某些專案反而礙事**。

如果你發現全域裡的某條準則,在新專案裡讓 agent 做了不合適的事——八成是當初有個「專案特有的東西」偷偷混進了全域。把它從全域移除,需要的話搬到對應專案的 CLAUDE.md。

其他該修剪的訊號:
- 某條準則你已經不再認同 / 改變了做法。
- 條目越積越多,重點被稀釋——全域準則貴精不貴多,定期砍掉低價值的。

## 怎麼隨經驗持續擴充

這份檔案應該是活的。建議的擴充時機:

- **每次踩到新雷**:當你又因為 agent 某個行為吃了虧、心想「以後一定要提醒它別這樣」——這就是一條新準則的雛形。過一下黃金法則,可遷移就加進去。
- **養成新協作習慣**:當你發現自己反覆對 agent 下某個指示,把它固化成準則,以後就不用每次手動講。
- **跨專案發現共同模式**:當你在第二、第三個專案又自然用了某個做法,代表它真的可遷移,值得入庫。

## 給未來的你:克制是美德

全域準則的天敵是膨脹。每多一條,agent 要消化的脈絡就多一分,真正重要的條目就被稀釋一分。

維持健康的心態是:**這份檔案是你的開發憲章,不是備忘錄。** 只放那些「你真心希望每個專案、每次協作都遵守」的核心原則。瑣碎的、只在特定情境成立的,留給專案層級的 CLAUDE.md。

定期（例如每隔幾個月、或每完成一個專案)回頭看一遍,問自己:「這些我現在還都認同嗎?有沒有哪條其實是某個專案的殘留?」——這個定期審視,就是這份檔案能長期保持鋒利的關鍵。
